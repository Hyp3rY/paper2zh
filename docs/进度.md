## 第 1 批（P0：环境跑通）— 已完成

### 三行复述（开工时写的）

- **本批目标**：在本机搭出「嵌入式 Python 3.12 + MinerU 4.2.2（不装 torch）+ standard 模型」的运行时，并用真实英文论文跑通 `parse → zip 产物`，记录每页耗时。
- **怎么验收**：`markdown.md` 里公式、图片、表格都在；zip 产物清单与提示词 4.1 对得上；`python -m mineru.kit.main version` 能跑；basic 和 standard 各有一组每页耗时数字。
- **不许做什么**：不写翻译代码、不碰第 4 节的核心实现、不开始打包（第 4 批）；不调用任何远程解析服务；不用系统 Python 3.14 替代自带运行时。

### 做了什么

1. **运行时**：CPython 3.12.10 embeddable（阿里镜像 10.6 MB，解压 21.5 MB）→ `runtime\python\`；
   `build/_pth_patch.py` 把 `../site-packages` 写进 `python312._pth` 并打开 `import site`（幂等 + 自校验）。
2. **pip**：不用 get-pip、不联网，把 `pip-25.3` wheel 直接解压进 `runtime\site-packages`。
3. **依赖**：`mineru==4.2.2`（无 torch）装到 `runtime\site-packages`，**760 MB / 34 382 文件 / 119 个包**；
   生成 `requirements.lock`（精确版本）。
4. **模型**：`mineru-kit models download --tier standard --source modelscope` → **2.0 GB**；
   `models verify --tier standard` 两个仓库都「正常」。
5. **跑通**：15 页 arXiv 论文，`-f zip`，standard / basic / CPU 模拟三种模式各一遍。

### 怎么证明能用

| 验收项 | 结果 |
|---|---|
| `python -m mineru.kit.main version` | ✅ `MinerU 版本: 4.2.2` / `Python 版本: 3.12.10`（692 ms） |
| SDK 三入口 import | ✅ `parse` / `render` / `RenderFormat`（607 ms） |
| zip 产物清单 | ✅ `markdown.md`、`middle_json.json`、`structured_content.json`、`images/`（14 张） |
| 公式 | ✅ 5 个行间公式（10 个 `$$`）、62 个行内公式（124 个 `$`） |
| 图片 | ✅ 5 个 `![](...)`，路径形如 `images/page_2_image_0.jpg` |
| 表格 | ✅ 2 个 `<table>`（HTML 字符串） |
| 模型校验 | ✅ `MinerU-4_models_onnx: 正常`、`MinerU2.5-Pro-2605-1.2B-GGUF: 正常` |
| 耗时 | standard **29.8 s / 15 页 = 1.36 s/页**；basic 36.2 s；CPU 模拟 106.9 s |

### 关键结论（详见 `docs/findings.md`）

1. **假设 A 有答案了**：行内公式是独立条目 `equation_inline`，正文里 0 个 `$` → **4.2 占位符机制可以砍掉**。
2. **假设 B 成立**：pydantic `MiddleJson.model_validate` → 改 `content` → `render()` 输出正常；
   不改内容重新渲染的结果与 MinerU 自己的 `markdown.md` **逐字节相同**（44 177 字符）。
3. **假设 C 基本有答案**：Windows 版 llama.cpp 只带 `ggml-vulkan.dll` + `ggml-cpu.dll`（无 CUDA），
   `MINERU_LLAMA_CPP_BACKEND` 也只接受 `auto|cpu|vulkan|metal`；Vulkan 档比 CPU 档多吃 1.9 GB 显存
   且快 5 倍 → **不需要 `--with-gpu` 补丁包**。缺一条直接证明 Vulkan 的 ggml 日志行，留第 2 批。
4. **本机 standard 比 basic 更快**（Vulkan+DirectML 并行），不是只在质量上更优。
5. **提示词 4 处漏洞已补**：`-o` 必填、embedded 无 pip、构建隔离必失败（`--no-build-isolation`）、
   `render()` 只吃 pydantic 模型。

### 结论

### 本批新挖到的两个「必须改设计」的点

1. **`page_number` / `aside_text` / `footer` 三类块根本不进 markdown**（Attention 251 条里少 16 条，
   Mask 234 条里少 13 条）。
   → 第 3 批分块要按「渲染得出来」筛，否则白翻。`ref_text`（参考文献）**会**渲染，
   必须显式排除，不能靠「不渲染」躲。
2. **QA 只数 `$$` 抓不到公式被污染**：把 LaTeX 换成中文串，`$$` 数仍是 10。
   → 必须逐块比对 equation 块 LaTeX 与原文完全一致。
   另外亲眼验证了「公式识别失败 → 以图片输出」：清空 equation 的 `content` 后，
   渲染器自动回退成 `![](images/page_3_equation_6.jpg)`，`$$` 从 10 变 8。

### 本批踩的坑（都写进 findings 了）

1. **嵌入式 Python 的 `._pth` 会关掉「脚本目录进 sys.path」**，`import paths` 直接 ModuleNotFoundError。
   每个入口必须自己 `sys.path.insert(0, ...)`，否则干净机器上第一次运行就炸。
2. **表格单元格里还有 `<eq>公式</eq>`**，按文本节点遍历会把公式送去翻译 → 破坏公式。

3. **只数 `$$` 抓不到公式被替换**：第一次破坏测试（数量法）**通过了**，加了 LaTeX 指纹才抓到。
   这条验证了第 2 批的判断。

## 追加：装进 WorkBuddy（国服/国际服）与豆包

### 怎么确认的（不是猜路径）

在你机器上逐个探测，并用域名判断哪个是国服：

| 客户端 | 目录 | 判定依据 |
|---|---|---|
| WorkBuddy 国服 | `%USERPROFILE%\.workbuddy\skills\` | 配置里出现 `workbuddy.cn` / `codebuddy.cn` / `copilot.tencent.com` |
| WorkBuddy 国际服 | `%USERPROFILE%\.workbuddy-ai\skills\` | 配置里出现 `codebuddy.ai` |
| 豆包 | `%LOCALAPPDATA%\Doubao\User Data\Default\.doubao\agent_mode\workspace\.user_skills\` | 同级 `.skills` 里是官方内置技能（含 `doubao-pdf`），`SKILL.md` 格式与本项目一致 |
| 豆包（旧位置） | `%USERPROFILE%\Doubao\skills\` | 目录存在但为空，一并写入兜底 |

两家的 `SKILL.md` 都只要求 `name` + `description` 开头，本项目现有文件直接兼容，无需改写。

### 改动

1. `install_skill.py` 改成**先探测再安装**：只写检测到的客户端目录，不会凭空造目录；
   `--list` 只看检测结果，`--dry-run` 只演练。
2. 新增 `--pack`：生成 `pdf2zh-skill.zip`（48.6 KB，根目录 `pdf2zh/SKILL.md`），
   给只支持「上传技能」的客户端手动导入。
3. `3-装进AI工具.cmd` 默认带上 `--pack`，装完包根目录就有一份可上传的技能包。
4. `config.json` 的 `skill_targets` 记录全部实际安装位置。

### 实测

六个目标全部写入成功（各 13 个文件，结构 `SKILL.md + scripts + references`）：
通用目录、Claude Code、WorkBuddy 国服、WorkBuddy 国际服、豆包用户技能目录、豆包旧目录。

⚠️ 未验证：WorkBuddy / 豆包是不是**重启后**就会在「技能」列表里认出来——
这需要你打开客户端看一眼。如果没出现，用生成的 `pdf2zh-skill.zip` 在客户端里「上传技能」即可。

## 追加：按两份真实使用评价修 bug

来源：`pdf2zh-skill-使用评价workbuddy-hy4flash.md`、`pdf2zh-技能评估-dsh-deepseekv41f.md`
（两份都由 agent 用它完整翻完一篇论文后写成）。逐条处理见 `docs/反馈处理.md`。

已修（均有回归测试）：

1. **长文件名 260 字符**：解析改到 `%TEMP%\pdf2zh-parse\<hash>`，产物目录名超 60 字符截断+哈希，
   拼接 >240 字符时直接报「文件名太长」。119 字符文件名的 PDF 已端到端跑通。
2. **`$A$ $B$` 粘成 `$A$$B$`**：`rebuild_spans()` 保留空白 span、相邻公式之间补空格。
3. **语言闸门把 `\mathrm`/`\circ` 当英文**：剥掉所有公式与 LaTeX 命令，失败时列出具体 uid。
4. **`--model` 缓存键失配导致重复发放**：`.model` 文件 + 旧产物回退到最后一条记录的模型名。
5. **翻译阶段进度不动**：`next` 现在写 `.progress.json`（已翻 x/y 段）。
6. **改术语表全篇作废**：缓存键改为「本段实际用到的术语」。
7. **`pause` 污染 `--json`**：`PDF2ZH_NO_PAUSE=1` 可关。
8. **两份代码漂移**：`doctor` 新增 skill 副本哈希比对（实测立刻抓出 4 处旧副本，同步后转「通过」）。
9. **硬件档位永远 basic**：所有 `subprocess.run` 补 UTF-8 解码。
10. **注水**：`(a)`、`(rad/s)` 这类标签允许原样交回。
11. **公式报错不指位置**：公式指纹带块编号。
